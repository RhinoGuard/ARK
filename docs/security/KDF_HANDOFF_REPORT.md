## Delivered changes

1. **Argon2id salt ownership**
   - Clarified that `ark-crypto` validates caller-supplied salts and derives a KEK; it does not generate random bytes.
   - Assigned creation/re-key salt generation to the future credential-lifecycle owner using the approved OS CSPRNG abstraction.
   - Required the exact persisted salt to be reused during unlock.
   - Corrected the public `derive_kek` documentation so it no longer describes the salt as randomly generated by the function.

2. **HKDF IKM provenance**
   - Documented that the 16-byte minimum is a length check, not proof of entropy or trusted origin.
   - Listed accepted production source categories and explicitly prohibited raw passwords and low-entropy identifiers as IKM.
   - Added a regression test demonstrating the distinction.

3. **Registered HKDF purposes**
   - Documented all six ARK v1 purposes and their intended subsystem ownership.
   - Defined compatibility expectations for exact purpose-label bytes.
   - Added a regression test locking all six labels and checking derivation separation.
   - Added secret-wrapper Debug redaction regression coverage.

4. **Argon2id calibration**
   - Added a six-profile benchmark harness reporting mean, median, p95, minimum, and maximum latency.
   - Added a manual GitHub Actions workflow for Ubuntu, Windows, and macOS, retaining raw output and runner metadata.
   - Clearly distinguished configured Argon2 memory from total process peak memory.

5. **Deferred boundaries**
   - Recorded why service-level error mapping cannot be implemented before a service/auth/session boundary exists.
   - Recorded why authenticated KDF metadata and migration cannot be implemented before a storage/credential persistence subsystem exists.

6. **PR reconciliation**
   - Recorded the PR #3 / PR #28 divergence and selected PR #28 as the staged integration candidate.
   - Kept PR #3 history untouched and did not create a second independent Crypto merge path.
